# Worlds release media

The standalone `trailer.html` stage renders the real Worlds generators, models,
textures, sky and post-processing. Character actions are staged cinematics.
It does not connect to a game server. The end card says **November 2026**, has no
URL, and loads the exact logo SVG from the game's title screen.

## Preview

Run `npm run dev`, then open `http://localhost:5174/trailer.html`. Select a shot
or press **Play preview**. The preview pauses while the next scene loads;
offline export has no loading gaps. Music is mixed into the exported video.

## Generate the original score

```sh
npm run trailer:music
```

`scripts/compose_trailer.mjs` synthesizes the original 80-second, 120 BPM score
**Worlds Awaken**. It exports 48 kHz / 24-bit stereo WAV, melody, atmosphere,
percussion and effects stems, and a machine-readable note list. No audio assets
or third-party samples are needed.

## Capture

Install Playwright with Chromium outside the project if preferred, and provide
FFmpeg. On machines without a GPU, Chromium uses SwiftShader and takes longer;
the simulation still advances at a fixed rate and produces smooth output.

```sh
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs \
FFMPEG=/path/to/ffmpeg npm run trailer
```

The script starts its own Vite server on port 5184 and closes it after capture.
`TRAILER_PORT`, `TEST_URL` and `CHROMIUM_PATH` override the defaults.

Options:

- `--stills-only` or `--video-only` (mutually exclusive)
- `--video-only --picture-only --shots=0,1,2,3` for cloud-compatible picture
  partitions; indices must be distinct, increasing and valid. Partial captures
  retain full-edit timestamps and cannot be muxed directly with the full score.
- `--width=1920 --height=1080 --fps=30`
- `--stills-width=3840` (16:9)
- `--quality=balanced` (fixed shader tier), `--quality=max`, or `--quality=high`
  (direct renderer without post-processing)
- `--output=release-media/revised` (the default)

Full outputs under `release-media/revised/` include the H.264/AAC MP4, original score and
stems, fourteen clean screenshots, two branded hero images, a thumbnail, an end
card, the logo SVG, and capture manifests. This generated directory is ignored
by Git. VP9/IVF is retained as the intermediate picture master.

Local capture, score composition, mixing, verification and full Modal downloads
use the same revised default. Supply a unique `--output` for review captures;
archived/published outputs are not regenerated by source validation. Stills-only
and video-only galleries link only their declared deliverables, so neither needs
files from a previous capture. Picture partitions write `picture-manifest.json`;
stills write `screenshots-manifest.json`; full masters write `manifest.json`.
Mixing requires both a nonempty music WAV and effects WAV. Full master creation
regenerates the score if either is absent, then uses the shared manifest-driven
`scripts/finish_trailer.mjs` encoder. Unsupported flags, quality settings, shot
filters and invalid numeric options fail with an explicit error.

## Modal cloud capture

With the Modal Python SDK installed and the existing account profile active:

```sh
modal run scripts/modal_trailer.py --proof
modal run scripts/modal_trailer.py
```

The proof exports review images only. The full run renders four video partitions
and the screenshots concurrently in cloud containers, then composes the extended
score, assembles the edit, and verifies it on Modal. It downloads final media to
`release-media/revised/`; audio stems stay in the `worlds-release-media` Modal
volume. Browser installs and intermediate frame streams stay in the cloud.

`scripts/publish_trailer.py` uploads the verified trailer, screenshot ZIP and
original score/stems directly from the Modal volume to an existing GitHub
Release. It uses the active `gh` login via an ephemeral secret. Large media is
published as Release assets, keeping Git history small.

The current edit is 80 seconds at 120 BPM (a bar is two seconds). It is cut from
`src/trailer/timeline.json`, which both the picture (`src/trailer/staging.ts`) and the
score (`scripts/compose_trailer.mjs`) read, so the sound effects land on the frames.
Every game gets a title card and shots that show how it is played: Bedwars
(protect the bed, gather and shop, bridge, break the bed, fight), The Bridge
(cross, fight on the span, score in the portal), Duels (burst-rifle fight),
Parkour (outrun the dragon to the sanctuary) and Rat and Seek (steal cheese, the
chase, free a caged friend), then a poster wall of the five games and the
**November 2026** end card with the early-access line. There is no Void Cape
teaser. Avatars hold items through the same `createAvatarEquipment` path the game
uses, so the hands in the trailer match what players see.

The capture script validates frame counts, propagates page and console errors,
and closes its browser/server even when initialization fails. Trailer mastering
uses two-pass normalization targeting −14 LUFS and −1.5 dBTP; the listening copy
targets −14 LUFS and −1 dBTP. Verification allows encoded loudness within 1 LUFS
and rejects true peaks above −0.5 dBTP.

`npm run trailer:check` audits camera clearance against the real world geometry.
After capture, `FFMPEG=/path/to/ffmpeg npm run trailer:verify` decodes the entire
MP4, checks frame count, resolution, audio loudness, unexpected black gaps, PNG
dimensions, full canonical logo identity and gallery links, then writes
`release-media/revised/verification.json`. Frame expectations derive from the
manifest's shot timeline and fps, including cloud partition assembly; publishing
does not assume a hard-coded frame total. Partition assembly verifies complete,
ordered shot coverage and matching IVF headers. The cloud retains score stems,
removes picture partitions/intermediates after mastering, and downloads final
deliverables; publication retains the existing versioned ZIP names and refuses
to overwrite a release asset.

## Card art and app branding

`cardart.html` renders five title-card scenes without a multiplayer server and
is included alongside the game/trailer in the build. Use explicit browser paths:

```sh
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs CHROMIUM_PATH=/path/to/chrome \
  npm run cards -- --only=bedwars,duels --output=node_modules/.tmp/card-review
```

`CARDS_PORT` defaults to 5185; `TEST_URL` reuses a supplied page server. The
normal output default remains `public/cards/` for intentional published-card
updates. Unknown, empty or duplicate card filters fail before capture. Game-card
capture does not regenerate the app icons or OG image; the retained branding
assets need a separate reviewed rasterization of the full title SVG, described
in `README.md`.
